# Lightfielder for DaVinci Resolve — Documentation Site

This folder contains the [Docusaurus](https://docusaurus.io/) powered
documentation site for the **Lightfielder for DaVinci Resolve** project. It is
published to GitHub Pages at:

https://lightfielder.github.io/Lightfielder-DaVinci-Resolve/

The site scaffolding, theme, Mermaid integration, and local search plugin are
inspired by the [VFXPedia](https://github.com/Lightfielder/VFXPedia) docs
project so the Lightfielder documentation reads as part of the same design
family.

## Folder Layout

```text
docs/
├── docusaurus.config.js     # Site configuration (title, navbar, footer, plugins)
├── sidebars.js              # Autogenerated sidebar entry point
├── package.json             # Node/npm dependencies and scripts
├── src/
│   ├── components/          # Inline MDX helpers (DocNote, DocWarn, ...)
│   ├── css/custom.css       # Global theme
│   ├── pages/index.js       # Custom homepage
│   └── theme/               # Swizzled Logo + MDX component mapping
├── static/
│   ├── img/                 # Logo, favicon, and static images
│   └── .nojekyll            # Required by GitHub Pages
└── docs/                    # The Markdown help content
    ├── index.md             # Docs landing page (Overview)
    ├── installation/        # Install Python, Install Lightfielder, Uninstall
    ├── usage/               # Toolbar overview, scripts, metadata, shotlog, ...
    ├── workflow-guides/     # In-depth workflow guides
    ├── project/             # ChangeLog, Known Issues, PunchList
    ├── Ops/                 # Lightfielder Ops (Operators) + Viewport docs
    ├── images/              # Shared screenshots
    └── assets/              # Sample Shotlog.csv and Toolbar_Default.json
```

The imported **Kartaverse Vonk Ultra** node reference lives outside `docs/` in
`vonkultra/` and is served as a second docs instance at `/VonkUltra/`. Its images
are under `static/img/vonkultra/`.

```text
docs/
├── vonkultra/               # Vonk Ultra docs (mdx), served at /VonkUltra/
├── sidebarsVonkUltra.js     # Four autogenerated sidebars for the Vonk Ultra docs
└── src/
    ├── components/CategoryCards.jsx   # Vonk Ultra category card grid
    ├── css/vonkultra.css              # Node badge / screenshot / icon styles
    └── data/categoryConfig.js         # Data-type + function-group card config
```

## Local Development

Install [Node.js](https://nodejs.org/en) (v20 or newer). In a terminal window,
navigate to this `docs/` folder and run:

```bash
npm install
npm start
```

The local staging server opens on port 2000:

http://localhost:2000/Lightfielder-DaVinci-Resolve/

Use `npm run build` to produce the static site in `docs/build/`, and
`npm run serve` to preview the production build locally.

## GitHub Pages Publishing

The workflow at [`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml)
builds this folder and publishes `docs/build/` to GitHub Pages on every push to
`main` that changes `docs/**`.

> Note: GitHub Actions only reads workflow files from the repository root
> `.github/workflows/` folder, so the workflow lives there even though the
> site itself is self-contained inside `docs/`.

Before the first deploy, make sure the repository's **Settings → Pages** source
is set to **GitHub Actions**.

## Editing the Content

The help topics are plain Markdown files under `docs/docs/`. Common edits:

- **Add a page:** create a `.md` file in the matching folder and add front
  matter (`title`, `sidebar_label`, `sidebar_position`, `description`). The
  sidebar is autogenerated from the folder structure.
- **Add a category:** create or edit a `_category_.json` file in the folder.
- **Link between pages:** use a relative path to the target `.md` file, e.g.
  `[Install Python](../installation/install-python.md)`.
- **Add a screenshot:** place the image in the relevant `images/` folder and
  reference it relatively, e.g. `![Alt text](../images/example.png)`.
- **Use custom components:** the site registers the `<DocNote>`, `<DocWarn>`,
  `<DocHeader>`, `<DocIndex>`, `<DocTitle>` and `<YouTubePlaylist>` helpers.
  Because `.md` files are parsed as plain Markdown, use a `.mdx` file when you
  want to embed those components or other JSX.
